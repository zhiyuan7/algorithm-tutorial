# 《Cpp——内存管理》内容建模

## 核心论证

中心问题：对象在内存中如何表示、存在多久，以及动态资源由谁释放？

文章从地址和布局出发，说明静态、自动、动态三种存储期的适用场景；随后比较 C 的字节分配与 C++ 的对象创建，指出手动释放容易泄漏，最终提出 RAII 和智能指针，把注意力转到所有权。

## 图谱边界

- **存储图**（`storage`）：描述对象的表示、地址、作用域与存储期。边表示“归属”“地址关联”和“自动生命期不足时转向动态存储”。
- **所有权图**（`ownership`）：描述动态资源的创建接口、手动释放风险与 RAII。边表示“对象语义扩展”“风险”和“责任转移”。
- 两图不是同一棵树。过渡镜头把“存在多久”换成“谁负责释放”，不把数据集合并。

## 内容校正

原文保留不改。演示中的技术口径作如下收紧：

1. 原文把自动对象“通常在栈上”解释为实现图景。演示明确区分**自动存储期**这个语言概念和物理栈位置，优化后对象可能不占栈空间。
2. 原文称全局静态对象在 `main()` 前完成初始化。演示不概括所有动态初始化的具体时机，只陈述静态存储期持续到程序结束；函数局部 `static` 首次执行到声明时初始化。
3. `#pragma pack` 不保证跨编译器可移植，紧凑布局可能产生未对齐访问；网络格式还要规定字节序。
4. `malloc` 示例使用 C 语法。演示提醒：`void*` 在 C++ 中不能隐式转换成 `int*`，且需检查分配失败和大小乘法溢出。
5. `shared_ptr` 引用计数无法自行解决循环持有；演示补充 `weak_ptr` 作为边界。

## 过渡节点映射

| 来源节点/组 | 过渡动作 | 目标节点/组 | 保留的意义 |
| --- | --- | --- | --- |
| 静态存储期 | 收拢淡出 | 无直接目标 | 不需要动态释放责任 |
| 自动存储期 | 向 RAII 一侧移动 | RAII | 作用域结束触发清理 |
| 动态存储期 | 向手动分配一侧移动 | malloc / new | 运行时获得资源与决定释放时机 |
| 指针保存地址 | 留作淡化语境 | unique_ptr / shared_ptr | 地址仍在，但被所有权封装 |
