# 《可计算理论》内容分析

## 一、核心问题与结论

文章围绕三个层次不同的问题展开：

1. 可计算性：一个问题是否存在保证正确、保证结束的算法。
2. 复杂度：在已经可判定的前提下，时间或空间随输入规模怎样增长。
3. 图灵完备：一个计算系统是否能模拟任意图灵机，从而表达所有可计算过程。

最终结论是：图灵完备描述“表达可计算过程的能力”，P / NP 描述“解决可判定问题的资源代价”，Decidable / Recognizable 描述“算法保证的边界”。三者不能混为一谈。

## 二、图谱边界

### 图谱 A：可计算性的停机承诺

根问题是“算法对 YES 与 NO 各承诺什么”。Decidable 严格包含于 Recognizable；`A_TM` 是可识别但不可判定的典型语言。对角线证明作为 `A_TM` 的局部推理链展开。

### 图谱 B：可判定域中的资源层级

根问题变为“算法终究会结束，但要多久”。以 `P ⊆ NP ⊆ Decidable` 为主轴，配合多项式增长、指数枚举、certificate、SAT 和 `P = NP?`。

### 图谱 C：计算系统的通用能力

根问题再次改变为“系统能表达哪些计算过程”。图灵完备由模拟能力、原则上可扩展的资源与不可计算边界共同刻画。条件分支、可扩展存储、无固定上限的循环或递归作为普通命令式语言中的直观充分构件，而不是普适形式定义。

## 三、变形映射

### A → B：从能不能算到要算多久

| 来源节点 / 组 | 过渡动作 | 目标节点 / 组 | 保留的意义 |
| --- | --- | --- | --- |
| Decidable | 保持主卡并上移 | Decidable | 所有复杂度类首先都必须可判定 |
| Recognizable | 向背景淡出 | 无 | 复杂度主线暂不讨论可能不终止的识别器 |
| `A_TM` / 对角线 | 收束为边界标记 | 图谱外边界 | 不可判定问题不进入 P / NP 资源竞赛 |
| “是否对所有输入停机” | 标签重写 | “停机需要多少资源” | 研究问题从存在性转为增长率 |

### B → C：从问题分类到机器能力

| 来源节点 / 组 | 过渡动作 | 目标节点 / 组 | 保留的意义 |
| --- | --- | --- | --- |
| Decidable | 收束为“可计算任务” | 可计算任务 | 能被算法完成的任务域 |
| P / NP / SAT | 折叠成资源刻度 | 时间与存储 | 快慢差异仍存在，但不决定图灵完备性 |
| 算法模型 | 中轴展开 | 图灵完备系统 | 从“问题属于哪一类”转到“系统能否模拟计算” |
| 不可判定边界 | 保持为底部边界线 | 只覆盖可计算任务 | 通用计算不能越过不可计算性 |

## 四、内容准确性修正

1. 原文 `3.1` 标题讨论 `A_TM`，伪代码却写成“只要 `M(w)` 停机就接受”，这识别的是 `HALT_TM`。演示明确区分：识别 `A_TM` 必须在模拟看到 `M` **接受**时才接受；若只看是否停机，则是 `HALT_TM`。
2. 原文把“拒绝停机”作为一种表述，容易与“停机并拒绝”混淆。演示统一为：非成员输入上，识别器可以停机拒绝，也可以永不停止。
3. 对 `A_TM` 的对角线机，若 `H` 预测“不接受”，`D` 接受；若预测“接受”，`D` 明确拒绝。这样直接得到接受与不接受的矛盾，不依赖把拒绝和死循环混写。
4. `P`、`NP` 和 `Decidable` 都按语言 / 判定问题理解。`NP ⊆ Decidable` 的理由是多项式长度证据空间有限且验证器总会停机；“指数枚举”是代价示意，不等于 NP 的定义。
5. “条件分支 + 可扩展存储 + 无固定上限循环/递归”保留为普通命令式系统的直观构造条件，不宣称它是所有计算模型的形式充要条件。
