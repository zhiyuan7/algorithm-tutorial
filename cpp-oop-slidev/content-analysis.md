# 内容分析：Cpp——面向对象

## 核心问题与论证

原文以机器人为贯穿案例，追问：怎样让数据和行为由合适的对象负责，并让不同类型通过稳定接口协作？论证先建立**单个对象的合法状态与生命周期**，再建立**对象家族的类型关系与运行时行为**。结论是：构造和析构守住资源边界，封装守住状态不变量；继承表达真实的 is-a，组合表达 has-a；虚函数让统一接口对不同实际对象产生不同行为。

## 图谱边界

- **图谱 A：一个对象如何保持合法**。关系是“建立／维护／释放／隐藏实现”，收纳构造、初始化、析构、RAII、默认特殊成员、封装、不变量和接口稳定性。
- **图谱 B：多个类型如何协作**。关系是“类型归属／接口契约／动态分派／创建与销毁”，收纳继承、组合、复用、三类成员函数、多态、工厂与虚析构。
- 过渡镜头将 A 中的 `encapsulation → contract`、`lifetime → virtual-dtor`、`object-root → dispatch` 显式对应。它讲的是设计关注点如何从单个对象扩展到对象家族；两图数据独立，过渡不是合并图谱。

## 演示中的技术修正

原文 `BankAccount` 示例的构造函数直接接受任意 `initial`，`withdraw` 也没有拒绝非正金额；因此代码本身不能保证文中强调的 `balance ≥ 0`。演示明确补上“构造时检查初始余额，取款时要求 `amount > 0` 且 `amount <= balance`”，原文文件保持不变。

“构造函数体赋值前成员先默认初始化”对类类型成员成立；对于没有类内初始化器的 `double` 等标量，默认初始化不会赋值，值可能不确定。演示在此处采用准确表述。

`= delete` 的含义是禁用指定函数；不等于所有对象都不可创建。演示以 `Task() = delete` 与可用的 `Task(int)` 并列说明。
