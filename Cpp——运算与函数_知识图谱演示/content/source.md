## 一、从数学中的“项”理解 C/C++ 中的运算

### 1. 项与函数

在数理逻辑中，一个“项（term）”大致可以理解为：**用于表示某个对象的符号表达式**。

最简单的项可以是变量或者常量，例如

\[
x,\qquad y,\qquad 3.
\]

之后，我们还可以利用函数构造更加复杂的项。例如如果 \(f\) 是一个一元函数，那么

\[
f(x)
\]

仍然是一个项；如果 \(g\) 是一个二元函数，那么

\[
g(x,y)
\]

也是一个项。

从这个角度来看，C/C++ 中大量所谓的“运算”，本质上都可以理解成函数。

例如：

```cpp
int a = 3;
int b = 5;

int c = a + b;
```

这里的

```cpp
a + b
```

从数学角度看，可以理解成

\[
+(a,b).
\]

也就是说，加法运算符 `+` 本质上对应一个二元函数：

\[
+\colon \mathbb Z\times\mathbb Z\to\mathbb Z.
\]

同样，

```cpp
a - b
a * b
a / b
```

可以分别理解成

\[
-(a,b),\qquad \times(a,b),\qquad /(a,b).
\]

因此，所谓“运算符”，可以看成是编程语言为了让某些非常常见的函数写起来更加自然，而提供的一种特殊语法。

我们习惯写

```cpp
a + b
```

而不是写成

```cpp
add(a, b)
```

但从抽象意义上讲，两者表达的思想其实十分接近。

加法严格来说通常是一个**二元函数**，因为它需要两个输入：

\[
+\colon A\times A\to A.
\]

### 2. C/C++ 中的运算还受到“类型”的约束

这里必须注意，程序语言中的运算并不完全等同于纯数学中的运算，因为程序中的每一个值都有具体的数据类型。

例如：

```cpp
int a = 5;
int b = 2;

int c = a / b;
```

此时

```cpp
a / b
```

得到的不是数学意义上的

\[
\frac52=2.5,
\]

而是整数

```cpp
2
```

因为 `a` 和 `b` 都是整数类型，C/C++ 中这里执行的是**整数除法**。

也就是说：

```cpp
5 / 2
```

得到

```cpp
2
```

而

```cpp
5.0 / 2.0
```

得到的才是

```cpp
2.5
```

类似地：

```cpp
5 / 2.0
```

也会得到浮点数 `2.5`，因为运算之前会发生类型转换，整数 `5` 会被转换为浮点类型。

因此，在 C/C++ 中理解一个运算，不能只问：

> “这是加法还是除法？”

还必须问：

> “参加运算的数据是什么类型？”

同一个符号，在不同类型下可能对应不同的具体运算规则。

这里还有一个很容易犯的错误：C/C++ **没有数学意义上的乘方运算符**。

例如：

```cpp
2 ^ 3
```

并不表示

\[
2^3.
\]

在 C/C++ 中，`^` 是**按位异或运算符**。

如果要计算乘方，通常需要使用函数，例如：

```cpp
#include <cmath>

double y = std::pow(2.0, 3.0);
```

此时才得到

\[
2^3=8.
\]

这恰好再次说明：所谓数学运算，未必一定要通过“运算符”表示，也完全可以通过普通函数表示。

## 二、函数：把已有的运算组合成新的运算

### 1. 函数的基本概念

既然加减乘除这些基本运算都可以看成函数，那么我们自然可以进一步构造自己的函数。

例如数学中可以定义：

\[
f(x)=x^2+2x+1.
\]

它实际上是由乘法、加法等更基本的函数复合而来的。

在 C++ 中可以写成：

```cpp
double f(double x)
{
    return x * x + 2 * x + 1;
}
```

从数学角度看，这段程序就是在构造一个新的映射：

\[
f\colon \mathbb R\to\mathbb R.
\]

当然，由于计算机中的 `double` 只是有限精度浮点数，所以严格来说它并不真的等于数学上的整个 \(\mathbb R\)，这里只是在结构上做类比。

一个最基本的 C/C++ 函数定义通常具有这样的结构：

```cpp
返回值类型 函数名(参数列表)
{
    函数体
    return 返回值;
}
```

例如：

```cpp
int add(int a, int b)
{
    int result = a + b;
    return result;
}
```

这里：

```cpp
int
```

表示函数返回值的类型；

```cpp
add
```

是函数名；

```cpp
int a, int b
```

是函数的输入参数；

而

```cpp
return result;
```

则给出函数最终产生的输出。

于是我们可以调用：

```cpp
int x = add(3, 5);
```

数学上可以近似地理解成：

\[
x=\operatorname{add}(3,5).
\]

得到

\[
x=8.
\]

函数当然并不一定只有一个输入。例如：

```cpp
double distance(double x, double y)
{
    return std::sqrt(x * x + y * y);
}
```

对应

\[
d(x,y)=\sqrt{x^2+y^2}.
\]

它是一个二元函数。

函数也可以没有需要返回的值，此时可以使用 `void`：

```cpp
void printHello()
{
    std::cout << "Hello\n";
}
```

这里这个函数的主要作用不是“计算并返回一个值”，而是产生某种行为，例如输出内容、修改对象或者改变程序状态。

所以程序语言中的“函数”实际上比数学中的函数稍微宽泛一些。数学中的函数强调

\[
\text{输入}\longmapsto\text{输出},
\]

而程序中的函数还可能存在**副作用（side effect）**。

例如：

```cpp
int count = 0;

void increase()
{
    count++;
}
```

这个函数虽然没有返回值，却修改了外部变量 `count`。

因此，把程序函数理解成数学函数非常有帮助，但不能认为二者完全相同。

### 2. 函数也是一个局部作用域

函数还有一个非常重要的作用：它会形成自己的**局部作用域（local scope）**。

例如：

```cpp
int add(int a, int b)
{
    int result = a + b;
    return result;
}
```

其中：

```cpp
a
b
result
```

都属于这个函数内部的局部名字。

特别是：

```cpp
int result
```

定义的是一个局部变量。

函数执行结束后，我们不能再在函数外直接使用这个变量：

```cpp
int add(int a, int b)
{
    int result = a + b;
    return result;
}

int main()
{
    std::cout << result;   // 错误
}
```

因为 `result` 只存在于 `add` 的作用域中。

这可以帮助我们理解为什么函数不仅仅是一种“计算工具”，也是程序组织结构的一部分：

\[
\boxed{
\text{函数不仅封装运算，也封装名字和局部状态。}
}
\]

### 3. 一个函数如何“返回多个值”

数学中一个函数似乎只能返回一个值：

\[
f(x)=y.
\]

实际上，这里的“一个值”完全可以是一个有序对：

\[
f(x)=(y_1,y_2).
\]

所以从数学上讲，“返回多个值”通常意味着：

> 把多个值组成一个更大的对象，然后返回这个对象。

程序设计中也是如此。

例如我们希望同时计算一个数组的最小值和最大值，可以定义一个结构体：

```cpp
struct MinMax
{
    int min;
    int max;
};
```

然后：

```cpp
MinMax getMinMax(int a, int b)
{
    MinMax result;

    if (a < b)
    {
        result.min = a;
        result.max = b;
    }
    else
    {
        result.min = b;
        result.max = a;
    }

    return result;
}
```

调用时：

```cpp
MinMax r = getMinMax(3, 8);

std::cout << r.min << '\n';
std::cout << r.max << '\n';
```

从数学上看，这个函数实际上就是：

\[
f(a,b)=(\min(a,b),\max(a,b)).
\]

C++ 中还可以使用 `std::pair`：

```cpp
std::pair<int, int> getMinMax(int a, int b)
{
    return {std::min(a, b), std::max(a, b)};
}
```

甚至使用结构化绑定：

```cpp
auto [minValue, maxValue] = getMinMax(3, 8);
```

这在形式上就已经非常接近数学里的

\[
(\text{minValue},\text{maxValue})
=
f(3,8).
\]

还有另一种很常见的方法：把需要修改的变量的地址传给函数。

在 C 中尤其常见：

```c
void getMinMax(int a, int b, int* minValue, int* maxValue)
{
    if (a < b)
    {
        *minValue = a;
        *maxValue = b;
    }
    else
    {
        *minValue = b;
        *maxValue = a;
    }
}
```

调用：

```c
int minValue;
int maxValue;

getMinMax(3, 8, &minValue, &maxValue);
```

这里函数形式上没有通过 `return` 返回两个值，而是接收了：

```c
int* minValue
int* maxValue
```

两个指针。

由于指针中保存了外部变量的地址，所以函数可以通过：

```c
*minValue = ...;
*maxValue = ...;
```

直接修改调用者提供的变量。

在 C++ 中还可以使用引用：

```cpp
void getMinMax(int a, int b, int& minValue, int& maxValue)
{
    minValue = std::min(a, b);
    maxValue = std::max(a, b);
}
```

因此，C/C++ 中所谓“返回多个值”，常见思路实际上有两大类：

\[
\boxed{
\text{多个值打包成一个对象返回}
}
\]

或者

\[
\boxed{
\text{把外部对象的地址/引用传入函数，由函数修改它们}
}
\]

前者更接近数学上返回一个有序组，后者则利用了程序具有可变状态这一特点。

### 4. 函数重载：让同一个名字适用于不同的输入

在数学中，我们常常用同一个符号表达形式相近、但作用对象不同的运算。例如 `+` 可以表示整数相加，也可以表示实数相加。在 C++ 中，普通函数也可以采用类似的做法：**同一个作用域内可以定义多个同名函数，只要它们的参数列表不同。**这称为函数重载（function overloading）。

例如，“求绝对值”这个动作对整数和浮点数都成立：

```cpp
int absolute(int x)
{
    return x < 0 ? -x : x;
}

double absolute(double x)
{
    return x < 0.0 ? -x : x;
}
```

调用时：

```cpp
int a = absolute(-3);        // 调用 absolute(int)
double b = absolute(-2.5);   // 调用 absolute(double)
```

程序会根据实参的类型，选择参数最匹配的那个版本。因此，调用者不必为“整数绝对值”和“浮点数绝对值”分别记住两个完全不同的名称。

函数能否构成重载，取决于它们的**参数列表**，包括参数的个数、类型或顺序。例如下面三者可以共存：

```cpp
void print(int value);
void print(double value);
void print(int value, int times);
```

但不能只靠返回值类型区别两个函数：

```cpp
int getValue();
// double getValue();  // 错误：只有返回值不同，不构成重载
```

因为当程序写下：

```cpp
getValue();
```

时，编译器无法仅从这次调用本身判断应当选择哪个版本。返回值类型是函数结果的类型，不是调用函数时用于选定版本的输入信息。

需要注意的是，重载并不是“只要同名就都可以”。如果一次调用需要经过多种同样合理的类型转换，编译器就可能无法决定该选哪一个版本：

```cpp
void process(int value);
void process(double value);

process('A');  // 通常会选择 process(int)，因为字符可提升为 int
```

当重载版本过多、参数类型又过于接近时，代码会变得难以理解，甚至产生二义性。因而重载适合表达**同一个概念在不同输入类型或不同参数数量下的自然变化**，例如 `absolute`、`print`、`max`；如果几个函数完成的其实是不同任务，使用不同的函数名通常更清晰。

## 三、从“项”进一步构造“公式”：关系运算

### 1. 原子公式

前面构造出来的：

\[
x,
\qquad
x+1,
\qquad
x^2+y^2
\]

本质上都表示某个“对象”或者“值”。

在数理逻辑中，我们通常把这样的东西叫做项。

但是：

\[
x+1<5
\]

就不再只是一个项了。

因为它提出了一个可以判断真假的陈述：

\[
\text{“}x+1\text{ 是否小于 }5\text{？”}
\]

从逻辑角度来看，我们可以利用**关系（relation）**把若干个项连接起来，从而产生一个原子公式。

例如：

\[
x<y
\]

可以理解成：

\[
<(x,y).
\]

其中“小于”实际上是一个二元关系。

C/C++ 中正好也提供了一系列关系运算符：

```cpp
<
>
<=
>=
==
!=
```

分别表示：

\[
<,\quad >,\quad \leq,\quad \geq,\quad =,\quad \neq.
\]

例如：

```cpp
int x = 3;
int y = 5;

bool result = x < y;
```

这里：

```cpp
x < y
```

的计算结果不再是一个普通整数，而是一个逻辑值：

```cpp
true
```

因为：

\[
3<5
\]

成立。

例如：

```cpp
5 == 5
```

结果为：

```cpp
true
```

而：

```cpp
5 != 5
```

结果为：

```cpp
false
```

于是我们可以看到一个非常自然的结构：

\[
\boxed{
\text{项}
\xrightarrow{\text{关系}}
\text{可以判断真假的表达式}
}
\]

例如：

```cpp
x + 1 < y * 2
```

可以拆成：

\[
\underbrace{x+1}_{\text{项}}
<
\underbrace{y\times2}_{\text{项}}.
\]

左右两侧首先通过运算构造出了两个值，然后使用 `<` 关系判断这两个值之间是否满足某种关系。

从逻辑的语言来说，这就非常接近一个**原子公式（atomic formula）**。

### 2. 从原子公式构造更加复杂的公式

有了原子公式之后，我们还可以使用逻辑运算继续组合它们。

例如：

\[
x>0
\]

是一个公式；

\[
x<10
\]

也是一个公式。

那么：

\[
(x>0)\land(x<10)
\]

就是一个更加复杂的公式。

它表示：

> \(x\) 大于 0，并且 \(x\) 小于 10。

C/C++ 中对应的是：

```cpp
x > 0 && x < 10
```

其中：

```cpp
&&
```

表示逻辑“与”。

C/C++ 中最基本的三个逻辑运算符是：

```cpp
&&
||
!
```

它们分别对应：

\[
\land,\qquad
\lor,\qquad
\neg.
\]

例如：

```cpp
x > 0 && x < 10
```

表示：

\[
(x>0)\land(x<10).
\]

而：

```cpp
x < 0 || x > 10
```

表示：

\[
(x<0)\lor(x>10).
\]

再例如：

```cpp
!(x == 0)
```

表示：

\[
\neg(x=0).
\]

也就是：

\[
x\neq0.
\]

例如：

```cpp
int age = 20;
bool hasTicket = true;

bool canEnter = age >= 18 && hasTicket;
```

这里实际上先形成了两个较简单的判断：

```cpp
age >= 18
```

以及

```cpp
hasTicket
```

之后再通过：

```cpp
&&
```

把它们组合起来。

其逻辑结构就是：

\[
(\text{age}\ge18)
\land
\text{hasTicket}.
\]

因此，从数学逻辑的角度，可以把它理解成：

\[
\boxed{
\text{变量和函数构造项}
}
\]

\[
\boxed{
\text{关系把项构造成原子公式}
}
\]

\[
\boxed{
\text{逻辑联结词把公式构造成更复杂的公式}
}
\]

这与 C/C++ 程序中大量条件表达式的构造方式高度相似。

还有一点十分重要：C/C++ 中的 `&&` 和 `||` 具有**短路求值（short-circuit evaluation）**的性质。

例如：

```cpp
p != nullptr && *p > 0
```

程序首先计算：

```cpp
p != nullptr
```

如果它已经是 `false`，整个

```cpp
A && B
```

就必然为 `false`，因此右边的：

```cpp
*p > 0
```

根本不会执行。

这不仅是一种逻辑规则，同时也是程序执行规则，因此可以避免在 `p == nullptr` 时错误地解引用空指针。

## 四、表达式

前面我们从数学角度区分了两类东西。

一类是“项”，例如：

\[
x+1,
\qquad
x^2+y^2.
\]

它们的作用是产生某个值。

另一类是“公式”，例如：

\[
x>0,
\]

或者：

\[
(x>0)\land(x<10).
\]

它们的作用是判断真假。

但是在 C/C++ 中，这两类东西都可以统一放到一个更加宽泛的概念下理解：

\[
\boxed{\text{expression（表达式）}}
\]

例如：

```cpp
x + 1
```

是一个表达式；

```cpp
x < 10
```

也是一个表达式；

```cpp
x > 0 && x < 10
```

仍然是一个表达式；

函数调用：

```cpp
f(x)
```

也是表达式；

甚至：

```cpp
x = 10
```

在 C/C++ 中本身也是一个表达式。

因此，“表达式”是 C/C++ 中一个比数学里的“项”更加宽泛的语法概念。

对于类似数学中“项”的表达式：

```cpp
x + 2 * y
```

它的求值结果可能是：

```cpp
17
```

这样的数值。

而对于类似数学中“公式”的表达式：

```cpp
x > 0 && y < 10
```

它的求值结果则可以是：

```cpp
true
```

或者：

```cpp
false
```

所以从直观上可以说：

\[
\boxed{
\text{项型表达式的值是某个对象}
}
\]

而：

\[
\boxed{
\text{公式型表达式的值是真或假}
}
\]

不过 C/C++ 又比纯粹的数理逻辑复杂一步，因为它允许不同类型之间进行一定程度的隐式转换。

例如在 C++ 中：

```cpp
if (5)
{
    std::cout << "Hello";
}
```

这里 `5` 本来是一个整数，并不是 `bool` 类型。

但是在需要布尔值的地方，它可以被转换为：

```cpp
true
```

基本规则是：

```cpp
0      -> false
非 0   -> true
```

因此：

```cpp
if (0)
```

条件不成立，而：

```cpp
if (100)
```

条件成立。

指针也具有类似性质。在布尔上下文中：

```cpp
nullptr
```

相当于 `false`，而一个有效的非空指针可以转换为 `true`。

例如：

```cpp
if (p)
{
    // p 非空
}
```

通常就等价于表达：

```cpp
if (p != nullptr)
{
    // p 非空
}
```

这种机制通常被称为类型转换，或者在这个具体语境下称为转换到布尔值、truth value conversion。

因此，程序设计中的“真假表达式”与数学逻辑中的公式虽然十分相似，却并非完全相同。数学逻辑通常严格区分：

\[
\text{项}
\]

和

\[
\text{公式},
\]

而 C/C++ 则把它们都放在“表达式”这一统一语法框架中，并允许某些原本不是布尔值的表达式在需要判断真假的上下文中转换成布尔值。
